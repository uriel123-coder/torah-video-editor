# Worked example: sucah

When the teacher explains the structure of a sucah, keep the teacher in a small PiP while an original three-wall/roof diagram builds in layers. As each condition is spoken, highlight only the relevant part and show the teacher's exact wording in the transcript ledger.

Suggested beats:

1. `presenter`: the question and why the structure matters.
2. `definition`: an abstract sucah diagram; label it `Diagrama explicativo`.
3. `measurement`: draw endpoints and display the unit exactly as taught; send any convention to review.
4. `source`: show the supplied Hebrew/Aramaic excerpt with a synchronized highlight.
5. `case`: split-screen only if two cases are explicitly compared.
6. `takeaway`: return to presenter full-frame; summarize without adding a ruling.

The example manifest in `examples/sucah-manifest.json` is intentionally source-unverified so it demonstrates the review state rather than pretending to cite a page.
